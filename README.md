# 3X APP

Telegram Mini App для управления конфигурациями в 3X-UI v3.8.5. Один Node.js-сервер обслуживает API и веб-интерфейс на HTML, CSS и JavaScript.

## Возможности

- Авторизация через подписанные Telegram `initData`.
- Заявки на доступ с кнопками «Подтвердить» и «Отклонить» в чате администратора.
- Группа `<tg_id>@3x.local` создаётся только после подтверждения.
- Настраиваемые типы клиентов. По умолчанию: TLS (VLESS + Hysteria) и AmneziaWG.
- Общий лимит — 10 клиентов, в любом сочетании, включая несколько клиентов одного типа.
- Email всех новых клиентов — последние 12 символов их Subscription ID + `@3x.local`. Например, `1e65490b-d757-4ddb-959e-bfcf03b448e4` → `bfcf03b448e4@3x.local`.
- Лимит каждого нового клиента: AmneziaWG — 50 GB, TLS — 200 GB. Квота общая для всех inbound’ов клиента.
- Расход трафика сбрасывается встроенным планировщиком 3X-UI первого числа месяца в полночь по часовому поясу панели; неиспользованный остаток не накапливается.
- Открытие страницы подписки. Кнопка «Удалить» устанавливает срок окончания на ближайшее первое число месяца, 00:00, без физического удаления клиента. Если expiryTime уже задан (в том числе отложенный срок), повторное действие запрещено. Клиент остаётся в списке и лимите 10. Автопродление при этом отключается.

Клиенты и группы загружаются из 3X-UI. Приложение не хранит их копию и не восстанавливает удалённую группу автоматически. Все клиенты учитываются в общем лимите. Старые клиенты `<tg_id>@3x.local` остаются доступны и также занимают одно место. Старые email и inbound’ы автоматически не изменяются; в интерфейсе адрес отображается по Subscription ID, а операции используют настоящий email из панели; клиенты других протоколов отображаются как «Другой протокол» и продолжают учитываться в лимите; их можно только открыть или назначить срок окончания.

## Запуск

Требуется Node.js 24 или новее.

```sh
npm ci
npm run dev
```

Перед запуском создайте локальный `.env` по примеру ниже. Подставьте собственные адреса, токены, Telegram ID и настройте существующие inbound’ы в `client-groups.json`.

```dotenv
NODE_ENV=development
PORT=8081
APP_ORIGIN=http://localhost:8081
TRUST_PROXY_HOPS=0
SUBSCRIPTION_TIMEZONE=Europe/Moscow

TELEGRAM_BOT_TOKEN=
TELEGRAM_ADMIN_CHAT_ID=
TELEGRAM_ADMIN_IDS=
APPROVALS_FILE=./data/approvals.json

XUI_URL=https://panel.example.com/secret-path/
XUI_API_TOKEN=
XUI_SUBSCRIPTION_URL=https://subscription.example.com/sub/
```

`XUI_URL` — базовый адрес панели, включая её префикс пути, без `/panel/api`. `XUI_SUBSCRIPTION_URL` — базовый адрес страницы подписки без идентификатора клиента. Типы клиентов и inbound’ы задаются в `client-groups.json`.

`TELEGRAM_ADMIN_CHAT_ID` — чат для заявок. `TELEGRAM_ADMIN_IDS` — Telegram ID пользователей, которым разрешено подтверждать заявки, через запятую. Для личного чата администратор должен сначала отправить боту `/start`.

Для открытия через Telegram опубликуйте сервер по HTTPS, укажите этот адрес без завершающего слеша в `APP_ORIGIN` и настройте кнопку меню Mini App через BotFather. За одним доверенным reverse proxy установите `TRUST_PROXY_HOPS=1`; без него оставьте `0`. При смене адреса временного туннеля обновите `.env`, кнопку бота и перезапустите сервер.

Обычное открытие страницы в браузере не заменяет вход через Telegram. Сервер проверяет подпись и срок действия `initData`.

## Эксплуатация

```sh
npm run check
npm run build
npm start
```

В production установите `NODE_ENV=production`. Для запуска нужны `dist/`, `public/`, `client-groups.json`, `package.json`, установленные production-зависимости и `.env`. Команды выполняются из корня проекта. Проверка доступности: `GET /api/health`.

Запускайте один экземпляр приложения: обработчик подтверждений использует Telegram long polling, а блокировки операций находятся в памяти процесса. Бот не должен одновременно использовать webhook или другой обработчик `getUpdates`.

`data/approvals.json` хранит заявки, результаты решений и позицию Telegram polling. Сохраняйте каталог `data/` между перезапусками. Это служебное состояние доступа, а не база VPN-конфигураций.

`.env`, `data/`, зависимости, сборка и логи исключены из Git. Токены передаются только серверу.

## Структура

- `src/auth/` — проверка авторизации Telegram.
- `src/access/` — заявки и решения администратора.
- `src/telegram/` — Bot API и обработка кнопок.
- `src/panel/` — клиент API 3X-UI.
- `src/profiles/` — получение, создание и удаление конфигураций.
- `public/` — интерфейс Mini App.

`npm run format` форматирует исходники. `npm run check` проверяет TypeScript и синтаксис браузерного JavaScript без обращений к панели.

## Docker и CI

GitHub Actions собирает образ для `linux/amd64` и `linux/arm64`. При push в `main` публикуются `ghcr.io/merzzzl/3x-app:latest` и тег коммита `sha-…`. Теги Git `v*` публикуются как одноимённые теги образа. Pull request проверяет сборку без публикации; также доступен ручной запуск workflow.

Публикация использует встроенный `GITHUB_TOKEN` с правом `packages: write`. Дополнительный токен не нужен. Настройка соответствует [документации Docker для GitHub Actions](https://docs.docker.com/build/ci/github-actions/push-multi-registries/).

```sh
# Локальная сборка
docker build -t x3-bot-app .

# Запуск опубликованного образа
docker run -d --name x3-bot-app --restart unless-stopped \
   --env-file .env -e NODE_ENV=production \
   -e APPROVALS_FILE=/app/data/approvals.json \
   -p 127.0.0.1:8081:8081 \
   -v x3-bot-app-data:/app/data \
   ghcr.io/merzzzl/3x-app:latest
```

В `.env` установите `PORT=8081`, публичный HTTPS-адрес в `APP_ORIGIN` и параметры доверенного reverse proxy. HTTPS-прокси должен направлять запросы на порт 8081. Образ работает от пользователя `node`; именованный volume сохраняет заявки между пересозданиями контейнера. Не запускайте контейнер одновременно с локальным экземпляром того же бота.

`.env` и локальные заявки не включаются в контекст Docker-сборки. Для приватного GHCR-пакета перед `docker pull` / `docker run` потребуется `docker login ghcr.io` с правом чтения пакетов.

Квоты задаются при создании клиента (`totalGB` в байтах, 1 GB = 1024³ байт, как в интерфейсе панели; `trafficReset=monthly`, `trafficResetDay=1`). Существующим клиентам лимиты автоматически не меняются. Повторное завершение частично созданного клиента сохраняет его текущую квоту и расход. Для выполнения сброса сама 3X-UI должна работать; приложение не запускает собственный планировщик.

`SUBSCRIPTION_TIMEZONE` задаёт часовой пояс окончания подписки (по умолчанию `Europe/Moscow`). Согласуйте его с часовым поясом 3X-UI для сброса квоты. После истечения срока доступ ограничивает 3X-UI; приложение не удаляет записи автоматически.

## Группы подключений

`client-groups.json` задаёт варианты создания и подписи карточек:

```json
[
  { "id": "tls", "name": "TLS", "inboundIds": [1, 2], "trafficGB": 200 },
  { "id": "amnezia", "name": "AmneziaWG", "inboundIds": [4], "trafficGB": 50 }
]
```

`id` — уникальный постоянный идентификатор типа, `name` — название в интерфейсе, `inboundIds` — ID inbound’ов панели, `trafficGB` — месячная квота клиента. Один inbound может принадлежать только одному типу, чтобы приложение однозначно определяло тип по данным панели. Для создания все inbound’ы типа должны существовать и быть включены. Настройки читаются при запуске; некорректный файл останавливает запуск.

Это группы подключений в интерфейсе. Группа владельца в 3X-UI по-прежнему называется `<tg_id>@3x.local`. Встроенные списки протоколов и переменные `XUI_*_INBOUND_ID` больше не используются. Для удаления типа из выбора уберите его из файла. Существующие клиенты автоматически не меняются; неопознанные остаются в списке и лимите.

Для Docker сохраните файл рядом с Compose и добавьте к существующим volumes:

```yaml
volumes:
  - ./data:/app/data
  - ./client-groups.json:/app/client-groups.json:ro
```

Затем выполните `docker compose up -d --force-recreate`. Пересборка образа при изменении подключённого файла не нужна. Другой путь можно задать переменной `CLIENT_GROUPS_FILE`.

Все новые клиенты получают `limitIp: 1` (Maximum simultaneous IPs). Лимиты трафика и IP применяются при создании, существующим клиентам автоматически не переписываются. Контроль одновременных IP выполняется средствами 3X-UI.

## Ключ Amnezia VPN

Нажатие на карточку открывает меню «Открыть подписку» / «Скопировать ключ».
Ключ `vpn://` формируется на сервере из текущей подписки 3X-UI после проверки
группы и владельца клиента. Ключи и содержимое подписок не сохраняются в базе
или логах; API-ответы запрещено кешировать. Для копирования нужен HTTPS.

VLESS, Trojan и Hysteria2 объединяются в `amnezia-xray`. Если подключений Xray
несколько, используется балансировщик `random` для новых соединений.
AmneziaWG добавляется отдельным контейнером `amnezia-awg`. Работают также ключи
только с Xray или только с AmneziaWG. Один ключ содержит не более одного AWG
контейнера. Экспорт поддерживает TCP/RAW, WebSocket, gRPC (включая authority), HTTPUpgrade,
XHTTP, TLS/REALITY и Hysteria2 с Salamander/Gecko. Сохраняются отпечатки
сертификатов, ECH, параметры REALITY и finalmask. Port hopping (`mport`) и
неподдерживаемые параметры отклоняются; устаревший `insecure` также отклоняется. Неподдерживаемые параметры вызывают ошибку, а не молча
исключаются из ключа; страница подписки остаётся доступной.

Это статический ключ: после изменения конфигурации нужно скопировать и
импортировать его заново. Совместимость протоколов зависит от версии Amnezia VPN.

Если подписка содержит MTProto, меню показывает «Открыть в Telegram» для каждого
адреса прокси. В Mini App используется `openTelegramLink`, в обычном браузере —
ссылка `https://t.me/proxy`. MTProto не включается в ключ Amnezia. «Скопировать
ключ» показывается только для подписок с Xray/AmneziaWG; ошибка его генерации не
скрывает ссылки Telegram. «Открыть подписку» отображается всегда (без настроенного
адреса подписки действие недоступно).

Ключи называются `<name> (<email>)`: `name` берётся из `client-groups.json`,
`email` — из записи клиента. Параметры VPN читаются только из subscription link;
API панели нужен для проверки владельца/группы и метаданных клиента.

Экспорт AWG сохраняет все параметры AWG 1.x/2/3.1, включая HeaderProtectionKey,
ContentPaddingAddition, интервалы, RandomTrailers и DisableCookies, как в
AmneziaVPN 5.0.3.0. Версия определяется по параметрам конфигурации; приложение
не превращает AWG 2 в AWG 3, если сервер не выдаёт параметры версии 3.
После обновления нужно заново скопировать ключ и импортировать подключение:
ранее выданные статические ключи автоматически не исправляются.
